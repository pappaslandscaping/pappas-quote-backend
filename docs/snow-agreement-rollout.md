# Snow agreement, 2026-27

The snow agreement is prepared for new, officially accepted HomeWorks estimates. It is disabled until `SNOW_AGREEMENT_ENABLED=true` is set. This branch has not been deployed and no client communication has been sent as part of its preparation.

## Agreement

`public/js/snow-agreement.js` supplies the versioned document and customer-facing HTML. `lib/snow-agreement-pdf.js` renders the same stored document. The signing page, HTML attachment fallback and downloaded PDF use that snapshot, rather than rebuilding terms from a changed template or catalog. Existing agreements are not converted or backfilled.

The winter version uses the accepted estimate for dates, price, payment schedule, snowfall trigger exceptions, included areas and salt. It keeps the existing 15-day written cancellation policy and seasonal no-refund wording. It replaces March renewal and mowing skip provisions with a stated winter period and a new estimate/agreement for a subsequent season. It does not add card, late or fuel fees. The liability section is a plain description of scope and reasonable care, not the former broad indemnity and liability-cap clauses; the draft should be reviewed as a complete replacement snow agreement before use.

Review the source estimate terms alongside the agreement before activation. Accepted estimate terms and notes are preserved in the document, so conflicting generic landscaping clauses in the source estimate should be corrected there. The draft is not a legal opinion about enforceability.

## Release and validation

1. Review the three-page agreement preview generated by `node scripts/render-snow-agreement-preview.js`.
2. Deploy the code and additive `contract_document` / `contract_document_hash` migrations with the switch off.
3. Confirm the 2026-27 HomeWorks estimate descriptions include explicit season years, start/end dates, service scope and payment arrangement. Each line needs the actual HomeWorks property ID. Estimates containing both winter and unrelated services must be split before using this template. Old-season or incomplete scopes are held for office review, without a new contract record being created.
4. Check a controlled seasonal, monthly, per-push and multi-property example end to end in staging, including the customer email, drawn/typed signatures, retained PDF and HomeWorks property media. This has not been tested against the live customer workflow.
5. Enable `SNOW_AGREEMENT_ENABLED=true` for new accepted estimates after review. Existing accepted-estimate polling and deduplication still apply. Older sent or signed agreements keep their prior content. Turning the switch off stops creation of further snow-template documents; it does not alter documents already issued.

## HomeWorks signed-copy location

The official GraphQL schema exposes `createUpload` and `addPropertyMedia`, but not an estimate-media attachment mutation. Signed PDFs are uploaded to each property referenced by the accepted estimate using those official operations. The estimate is not reaccepted and billing/status is not changed. Successfully attached properties are recorded in `quote_events` for retry deduplication. Failures return an error and are logged; the signed YardDesk copy remains downloadable. The existing signed-contract-sync endpoint can retry this path.
